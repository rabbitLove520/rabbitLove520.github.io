## 模型权重分类

### 各模块量级汇总（Llama 3.1 8B 粗算）

| 模块 | 参数名 | 单层/单模块量级 | 总层数 | 总量级 |
|---|---|---|---|---|
| 词嵌入 | `embed_tokens.weight` | 约 5.25 亿 | 1 | 约 5.25 亿 |
| 注意力 Q/K/V/O | `q_proj` / `k_proj` / `v_proj` / `o_proj` | 约 42M（GQA 下 K/V 小） | 32 | 约 13.4 亿 |
| MLP SwiGLU | `gate_proj` / `up_proj` / `down_proj` | 约 176M | 32 | 约 56.3 亿 |
| 归一化 | `input_layernorm` / `post_attention_layernorm` / `model.norm` | 极小 | — | 可忽略 |
| 输出层 | `lm_head.weight` | 约 5.25 亿 | 1 | 约 5.25 亿 |

可以看到，**MLP 是稠密模型参数的最大头**，其次是注意力，嵌入和 `lm_head` 各占约 5 亿量级。当层数增加时，`L × (注意力 + MLP)` 会迅速超过 `2Vd` 的嵌入/输出项。

### 更新权重完整链路

```
输入文本: "我 爱 吃 苹 果"
                │
                ▼
        ┌───────────────┐
        │  分词器 Tokenizer │  → token IDs: [1024, 305, 778, 9012, 66]
        └───────────────┘
                │
                ▼
   ┌────────────────────────┐
   │ 嵌入矩阵 Embedding Matrix │  查表：每行 512 维
   │  [词表大小, 512]         │  → 5 个 512 维向量
   └────────────────────────┘
                │  (+ 位置编码)
                ▼
   ┌────────────────────────┐
   │ Transformer Layer 1     │
   │  ├─ 自注意力 W_Q/W_K/W_V/W_O │
   │  └─ FFN  W_1/W_2/W_3    │
   └────────────────────────┘
                │
                ▼
   ┌────────────────────────┐
   │ Transformer Layer 2     │
   │  ...                    │
   └────────────────────────┘
                │
                ▼
   ┌────────────────────────┐
   │ 输出层 lm_head           │  → 每个位置对全词表的打分(logits)
   └────────────────────────┘
                │
                ▼
        ┌───────────────┐
        │  计算 Loss      │  预测"下一个词" vs 真实下一个词
        └───────────────┘
                │
                ▼  反向传播（Backpropagation）
   ┌────────────────────────────────────────┐
   │ 梯度从输出层往回传，逐层计算 ∂L/∂W      │
   │ 每一层的权重都收到属于自己的梯度         │
   └────────────────────────────────────────┘
                │
                ▼
   ┌────────────────────────┐
   │ 优化器 Adam/SGD 更新所有权重 │
   │ W ← W - lr × 梯度          │
   └────────────────────────┘
```

关键点：**token 本身不"更新权重"**。token 只是数据；真正更新权重的是"这个 token 参与前向计算后产生的 loss，经反向传播算出的梯度"。token 是触发者，梯度是执行者。

### 分步拆解：一个 token 的"一生"

以句子 `"我爱吃苹果"` 为例，模型做的是**下一个词预测**。每个位置都有一个预测任务：

| 输入到位置 | 模型要预测 | 真实答案 |
|---|---|---|
| 我 | 下一个词 | 爱 |
| 我爱 | 下一个词 | 吃 |
| 我爱吃 | 下一个词 | 苹 |
| 我爱吃苹 | 下一个词 | 果 |

**Step 1：前向——token 变成向量并逐层变换**

```
token "苹" (ID 9012)
   │ 查嵌入矩阵第 9012 行
   ▼
向量 e = [0.12, -0.03, ..., 0.88]  (512 维)
   │ + 位置编码
   ▼
送入 Layer 1：x1 = Attention(e) → FFN(...)
送入 Layer 2：x2 = Attention(x1) → FFN(...)
   ...
送入 Layer N：xN
   ▼
lm_head(xN) → logits [词表大小]
   ▼
softmax → 每个词的概率
```

**Step 2：算 loss——只看"预测下一个词"错了多少**

```
预测分布 P = [..., "果": 0.7, "子": 0.1, ...]
真实答案 = "果"
Loss = -log P("果")   ← 交叉熵
```

如果预测对了且概率高，loss 小；预测错或概率低，loss 大。

**Step 3：反向传播——梯度从输出层往回"倒灌"**

这是核心。链式法则把 loss 对**每一个参数**的偏导算出来：

```
∂L/∂lm_head        ← 输出层梯度
∂L/∂LayerN.FFN     ← 第 N 层 FFN 梯度
∂L/∂LayerN.Attn    ← 第 N 层注意力梯度
   ...
∂L/∂Layer1.Attn
∂L/∂Embedding[9012] ← 只有"苹"这一行收到梯度！
```

注意最后一行：**嵌入矩阵只有被命中的那些行有梯度**。这句话里命中的是 1024、305、778、9012、66 这 5 行，其余几万行这一轮梯度为 0。而注意力/FFN 是稠密矩阵，**每个元素都收到梯度**。

**Step 4：优化器更新——每个权重挪一小步**

```
W_new = W_old - lr × (梯度 + 动量/自适应项)
```

- 嵌入矩阵第 9012 行：`E[9012] -= lr × ∂L/∂E[9012]`
- 每一层的 W_Q/W_K/W_V/W_O、W_1/W_2/W_3：全部按各自梯度更新
- LayerNorm 的 γ/β：也更新

**一次迭代 = 一次前向 + 一次反向 + 一次更新。** 一个 batch（比如 32 条句子）会把这些句子里所有 token 的梯度**累加/平均**后再更新一次。

---

### "一点点"体现在哪：训练是海量迭代的累积

单次更新幅度很小（lr 通常 1e-4 ~ 1e-5 量级），但重复**几十万到几百万步**后，权重逐渐收敛：

```
第 1 步：    权重随机，loss 很高（比如 10+）
第 100 步：  loss 降到 7
第 1万步：   loss 降到 4
第 10万步：  loss 降到 2.5
第 100万步： loss 趋于平稳（比如 1.8）
```

每一步里：
- **嵌入矩阵**：高频 token 的行被反复微调，语义逐渐成形；低频 token 的行更新次数少，质量差一些。
- **注意力矩阵**：逐渐学会"代词该关注哪个名词""动词该关注宾语"等模式。
- **FFN**：逐渐记住大量事实知识和语言规律。

### 几个容易被忽略但很关键的细节

1. **一个 token 的梯度会"分摊"到所有层**。同一个 loss，既调整输出层，也调整中间层，还调整嵌入行。不是"token 只更新嵌入矩阵"。

2. **梯度是累加的，不是逐 token 串行更新**。一个 batch 内所有 token 的前向并行做完，loss 汇总，反向一次算总梯度，再统一更新。所以是"一批 token 共同推动权重挪一步"。

3. **嵌入矩阵的更新是稀疏的，注意力/FFN 是稠密的**。这也是为什么嵌入矩阵可以用稀疏优化器、而主体权重不行。

4. **共享嵌入与 lm_head**：很多模型让输出层和嵌入矩阵共享同一份权重（weight tying），此时同一个矩阵既在前向入口被查表、又在出口被矩阵乘，梯度从两头汇入。

5. **位置编码**：如果是可学习的位置编码，它也在这条链里被更新；如果是 RoPE 这种旋转式，则不占参数、不更新。
