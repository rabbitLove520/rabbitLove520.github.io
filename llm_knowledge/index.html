关键点：token 本身不"更新权重"。token 只是数据；真正更新权重的是"这个 token 参与前向计算后产生的 loss，经反向传播算出的梯度"。token 是触发者，梯度是执行者。

分步拆解：一个 token 的"一生"

以句子 "我爱吃苹果" 为例，模型做的是下一个词预测。每个位置都有一个预测任务：

输入到位置模型要预测真实答案
我下一个词爱
我爱下一个词吃
我爱吃下一个词苹
我爱吃苹下一个词果

Step 2：算 loss——只看"预测下一个词"错了多少

1
2
3

预测分布 P = [..., "果": 0.7, "子": 0.1, ...]
真实答案 = "果"
Loss = -log P("果")   ← 交叉熵

如果预测对了且概率高，loss 小；预测错或概率低，loss 大。

Step 3：反向传播——梯度从输出层往回"倒灌"

这是核心。链式法则把 loss 对每一个参数的偏导算出来：

∂L/∂lm_head        ← 输出层梯度
∂L/∂LayerN.FFN     ← 第 N 层 FFN 梯度
∂L/∂LayerN.Attn    ← 第 N 层注意力梯度
   ...
∂L/∂Layer1.Attn
∂L/∂Embedding[9012] ← 只有"苹"这一行收到梯度！

注意最后一行：嵌入矩阵只有被命中的那些行有梯度。这句话里命中的是 1024、305、778、9012、66 这 5 行，其余几万行这一轮梯度为 0。而注意力/FFN 是稠密矩阵，每个元素都收到梯度。

Step 4：优化器更新——每个权重挪一小步

1

W_new = W_old - lr × (梯度 + 动量/自适应项)
  • 嵌入矩阵第 9012 行：E[9012] -= lr × ∂L/∂E[9012]
  • 每一层的 W_Q/W_K/W_V/W_O、W_1/W_2/W_3：全部按各自梯度更新
  • LayerNorm 的 γ/β：也更新

一次迭代 = 一次前向 + 一次反向 + 一次更新。 一个 batch（比如 32 条句子）会把这些句子里所有 token 的梯度累加/平均后再更新一次。

“一点点"体现在哪：训练是海量迭代的累积

单次更新幅度很小（lr 通常 1e-4 ~ 1e-5 量级），但重复几十万到几百万步后，权重逐渐收敛：

1
2
3
4
5

第 1 步：    权重随机，loss 很高（比如 10+）
第 100 步：  loss 降到 7
第 1万步：   loss 降到 4
第 10万步：  loss 降到 2.5
第 100万步： loss 趋于平稳（比如 1.8）

每一步里：

  • 嵌入矩阵：高频 token 的行被反复微调，语义逐渐成形；低频 token 的行更新次数少，质量差一些。
  • 注意力矩阵：逐渐学会"代词该关注哪个名词"“动词该关注宾语"等模式。
  • FFN：逐渐记住大量事实知识和语言规律。

几个容易被忽略但很关键的细节

  1. 一个 token 的梯度会"分摊"到所有层。同一个 loss，既调整输出层，也调整中间层，还调整嵌入行。不是"token 只更新嵌入矩阵”。

  2. 梯度是累加的，不是逐 token 串行更新。一个 batch 内所有 token 的前向并行做完，loss 汇总，反向一次算总梯度，再统一更新。所以是"一批 token 共同推动权重挪一步”。

  3. 嵌入矩阵的更新是稀疏的，注意力/FFN 是稠密的。这也是为什么嵌入矩阵可以用稀疏优化器、而主体权重不行。

  4. 共享嵌入与 lm_head：很多模型让输出层和嵌入矩阵共享同一份权重（weight tying），此时同一个矩阵既在前向入口被查表、又在出口被矩阵乘，梯度从两头汇入。

  5. 位置编码：如果是可学习的位置编码，它也在这条链里被更新；如果是 RoPE 这种旋转式，则不占参数、不更新。

如果你想要真正的图，推荐搜这几个关键词看示意图：“Transformer forward backward pass diagram”、“LLM training loop diagram”、“backpropagation through transformer layers”。核心结构就是我上面文字图的样子：一条从 token→嵌入→N 层→输出→loss 的前向链，和一条从 loss 倒灌回每一层权重的反向链，优化器在链尾统一更新。
